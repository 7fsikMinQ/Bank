## 1. Windows 로컬 MariaDB

### 1-1. 설치 (MSI)

1. MariaDB **10.11.19** MSI(Windows x64)를 설치합니다.
2. 설치 화면에서:
   - root 비밀번호: 직접 정해서 입력 (기억해 두세요)
   - **"Enable access from remote machines for 'root' user" 는 체크하지 않습니다.**
   - **"Use UTF8 as default server's character set" 도 체크하지 않습니다.** (개발 서버가 latin1 기본이라 맞춥니다)
   - 서비스 이름 `MariaDB`, 포트 `3306`
3. 설치가 끝나면 `C:\Program Files\MariaDB 10.11\data\my.ini` 를 메모장(관리자)으로 엽니다.

### 1-2. my.ini 설정

설치기가 만든 기존 줄(`datadir`, `port`, `innodb_buffer_pool_size`, `plugin-dir`)은 **그대로 두고**, 아래 줄을 해당 구역에 추가합니다.

```
[mysqld]
character-set-server=latin1
collation-server=latin1_swedish_ci
sql_mode=IGNORE_SPACE,STRICT_TRANS_TABLES,ERROR_FOR_DIVISION_BY_ZERO,NO_AUTO_CREATE_USER,NO_ENGINE_SUBSTITUTION
max_allowed_packet=1G
lower_case_table_names=2
default-time-zone='+09:00'
bind-address=127.0.0.1

[client]
max_allowed_packet=1G
```

### 1-3. 서비스 재시작 (관리자 PowerShell 필요)

```powershell
Start-Process powershell -Verb RunAs
```

새로 뜬 관리자 PowerShell에서:

```powershell
Restart-Service MariaDB
```

### 1-4. 설정 확인 (root 비밀번호 직접 입력)

```powershell
& "C:\Program Files\MariaDB 10.11\bin\mariadb.exe" -h 127.0.0.1 -P 3306 -u root -p -e "SELECT @@port, @@version, @@character_set_server, @@lower_case_table_names, @@time_zone, @@max_allowed_packet"
```

기대값: 포트 3306, 10.11.19-MariaDB, latin1, 2, +09:00, 1073741824

### 1-5. 계정 만들기 → 데이터 복원

PowerShell은 `<` 를 쓸 수 없어서 `cmd /c` 로 감쌉니다. 각각 root 비밀번호를 입력합니다.

```powershell
cmd /c '"C:\Program Files\MariaDB 10.11\bin\mariadb.exe" -h 127.0.0.1 -P 3306 -u root -p < C:\kigte_backup\01_user.sql'
```

```powershell
cmd /c '"C:\Program Files\MariaDB 10.11\bin\mariadb.exe" -h 127.0.0.1 -P 3306 -u root -p --max-allowed-packet=1G < C:\kigte_backup\kigte_dev_20261028.sql'
```

수 분 걸리고, 끝나면 프롬프트만 돌아옵니다(에러 문구가 없어야 정상).

계정 확인:

```powershell
& "C:\Program Files\MariaDB 10.11\bin\mariadb.exe" -h 127.0.0.1 -P 3306 -u root -p -e "SELECT user, host FROM mysql.user WHERE user='kigte'"
```

`kigte | %` 가 나와야 합니다. 검증은 5장으로 갑니다.

## 2. WSL 직접 설치 (Ubuntu)

백업 파일이 `C:\kigte_backup` 에 있다고 가정합니다.

### 2-1. 파일을 WSL 안으로 복사

```bash
mkdir -p ~/kigte_backup && cp /mnt/c/kigte_backup/kigte_dev_20261028.sql /mnt/c/kigte_backup/01_user.sql ~/kigte_backup/ && ls -lh ~/kigte_backup
```

### 2-2. MariaDB 10.11 설치

```bash
sudo apt update && sudo apt install -y curl apt-transport-https ca-certificates
```

```bash
curl -LsS https://r.mariadb.com/downloads/mariadb_repo_setup | sudo bash -s -- --mariadb-server-version="mariadb-10.11"
```

```bash
sudo apt install -y mariadb-server mariadb-client
```

```bash
mariadb --version
```

### 2-3. 설정 파일 (복원 전에)

```bash
sudo tee /etc/mysql/mariadb.conf.d/99-kigte.cnf > /dev/null <<'EOF'

port=3308
bind-address=127.0.0.1

[client]
```

### 2-4. 시작과 설정 확인


```bash
sudo mariadb -e "SELECT @@port, @@version, @@character_set_server, @@lower_case_table_names, @@time_zone, @@max_allowed_packet"
```

기대값: 3308, 10.11.x-MariaDB, latin1, 0, +09:00, 1073741824

### 2-5. 계정 → 복원


```bash

```

접속 확인(비밀번호는 개발 `kigte` 계정과 같은 값, 직접 입력):

파일 이름이 `01_`, `02_` 로 시작해야 순서대로 실행됩니다. 이 폴더는 SVN/Git에 올리지 마세요.

### 3-2. 설정 파일

### 3-3. docker-compose.yml

```bash
cat > ~/kigte-docker/docker-compose.yml <<'EOF'
services:
  mariadb:
    image: mariadb:10.11.19
    container_name: kigte-mariadb
    restart: "no"
    environment:
      MARIADB_ROOT_PASSWORD: ${MARIADB_ROOT_PASSWORD}
      TZ: Asia/Seoul
    ports:
      - "127.0.0.1:3307:3306"
    volumes:
      - kigte_data:/var/lib/mysql
      - ./conf/99-kigte.cnf:/etc/mysql/conf.d/99-kigte.cnf:ro
      - ./init:/docker-entrypoint-initdb.d:ro
    healthcheck:
      test: ["CMD", "healthcheck.sh", "--connect", "--innodb_initialized"]
      interval: 10s
      timeout: 5s
      retries: 30
      start_period: 600s

volumes:
  kigte_data:
EOF
```

### 3-4. root 비밀번호 파일 (직접 입력, `$` 와 따옴표는 쓰지 않기)

```bash
cd ~/kigte-docker && read -s -p "root 비밀번호 입력: " PW && echo && printf 'MARIADB_ROOT_PASSWORD=%s\n' "$PW" > .env && chmod 600 .env && unset PW
```

### 3-5. 이미지 받기 → 시작

```bash
docker pull mariadb:10.11.19
```

태그를 못 찾으면 `mariadb:10.11` 로 바꾸고 compose의 `image` 줄도 같이 바꿉니다.

```bash
cd ~/kigte-docker && docker compose up -d
```

첫 시작은 데이터를 넣느라 수 분 걸립니다.

```bash
docker logs -f kigte-mariadb
```

`MariaDB init process done. Ready for start up.` 이후 `ready for connections` 가 한 번 더 나오면 완료입니다. `Ctrl+C` 로 로그만 끝내도 컨테이너는 꺼지지 않습니다.

```bash
docker compose ps
```

`STATUS` 가 `healthy` 이면 정상입니다.

### 3-6. 평소 사용

```bash
cd ~/kigte-docker && docker compose stop
```

```bash
cd ~/kigte-docker && docker compose start
```

처음 상태로 다시 복원하려면(이 컨테이너 DB가 모두 지워지고 자동 복원이 처음부터 다시 실행됨):


## 8. 자주 나는 문제

| 증상 | 원인과 조치 |
|---|---|
| `Restart-Service` 가 "서비스를 열 수 없습니다" | 관리자 PowerShell로 다시 실행 |
| PowerShell에서 `<` 오류 | `cmd /c '...'` 로 감싸서 실행 |
| `ERROR 1045 Access denied` | 비밀번호 오타(한글 입력 모드, 대소문자). root/kigte 계정과 비밀번호를 구분 |
| `ERROR 2006 / max_allowed_packet` | `--max-allowed-packet=1G` 와 설정 파일의 `max_allowed_packet=1G` 확인 |
| 복원 시 한글이 깨짐 | 덤프를 `>` 로 다시 만들었는지 확인(PowerShell의 `>` 는 UTF-16으로 저장됨). 덤프는 `--result-file` 로만 생성 |
| Docker가 안 올라옴 / 자동 적재 안 됨 | `docker logs kigte-mariadb` 확인. 자동 적재는 **볼륨이 비어 있을 때 처음 한 번만** 실행됨. 다시 하려면 `docker compose down -v` 후 `up -d` |
| 포트 사용 중 | 3306/3307/3308 중 겹치는 프로그램 종료 |

## 9. 집에서 운영 서버에 접속하려면 (결정 전에 모을 정보)

집 PC에서 먼저 값만 모읍니다. **방화벽은 결과를 보고 결정하기 전에는 바꾸지 마세요.**

1. 인터넷에서 보이는 내 IP (A):

```powershell
Invoke-RestMethod https://api.ipify.org
```

2. 공유기 관리 화면 주소(기본 게이트웨이):

```powershell
(Get-NetIPConfiguration | Where-Object { $_.IPv4DefaultGateway }).IPv4DefaultGateway.NextHop
```

그 주소를 브라우저로 열고 로그인해서 상태/인터넷/WAN 화면의 WAN IP (B)를 봅니다.

3. 공유기 화면에 못 들어가면:

```powershell
tracert -d 8.8.8.8
```

둘째 줄이 사설 대역이면 건물 NAT입니다(`*` 이면 판단 불가).

4. 판단표:

| 결과 | 의미 | 권장 |
|---|---|---|
| B가 A와 같음 | 가구 전용 공인 IP로 보임 | 방화벽에 SSH(22)만 임시 등록, DB는 DBeaver SSH 터널. IP가 바뀌면 그때 수정 |
| B가 `10.x`, `172.16~31.x`, `192.168.x`, `100.64~127.x` | 단지 공유 IP(이웃도 같은 IP 사용), 유동 가능 | 방화벽 등록은 비권장. 고정 IP 중계 서버(유료) 검토 |

5. 회사에서 운영 DB 연결로 (읽기 전용 조회):

```sql
SHOW GRANTS FOR CURRENT_USER();
```

`'계정'@'%'` 이면 접속 위치 제한이 없는 계정, 특정 IP만 적혀 있으면 방화벽을 열어도 집에서는 접속되지 않습니다.
