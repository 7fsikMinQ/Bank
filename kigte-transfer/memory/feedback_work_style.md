- **실제 소스(`src/main`) 수정은 사용자가 "하라/적용해줘"고 할 때만 한다.** 구현안·시안은 `0831요구사항/구현안_*` 같은 별도 폴더에 만들고, 사용자가 요청하면 삭제(롤백)한다. **Why:** 사용자가 직접 소스를 반영·커밋·배포하며(SVN, 7번부터 직접 적용), 의도치 않은 변경을 싫어함. **How to apply:** 분석·문서·구현안까지만 하고, 적용 전 "적용할까요" 확인. 시안을 만들었다면 끝에 롤백 필요 여부를 확인.
- **빌드·컴파일은 사용자가 불필요하다고 한 적 있음**(문서·소스 원문 중심). 검증은 필요 시 `javac`/`tsc`/스크립트로 임시 폴더에서만 하고, 프로젝트(`target` 등)는 건드리지 않는다. 사용자가 실행을 거부한 도구 호출은 반복하지 말고 방식을 바꾼다.
- **고객·이사님 답변 글은 사용자의 기존 양식(번호 항목, `·` 목록, `■`/`[N | 페이지]`, 서명)에 맞춰 바로 복사 가능한 코드블록으로** 준다. 카톡 문의에 대한 답변이면 제목·서명 없이 짧은 메시지로. 공수 숫자·금액은 사용자가 요청한 때만 넣고, "보수적으로" 같은 내부 표현은 쓰지 않는다. 가/나 같은 내부 논의 과정은 메일에 넣지 않고 "협의 완료된 최종 방식 + 작업 내용 + 반영 일정" 위주로 쓴다.
- **"N회 분석·검토" 요청은 같은 확인을 N번 반복하는 대신 서로 다른 관점(소스·SQL·VO·화면·API·문서·PDF 이미지)으로 나눠 확인하고, 실DB·실화면 미실행 같은 한계와 "1% 이상 없음은 보증 불가"를 정직하게 밝힌다.**
- 사용자는 영문 자판 상태로 한글을 쳐서 보낸 문장이 있을 수 있음 — 두벌식으로 복원해 의도를 파악한다(복원 스크립트는 세션 임시 폴더에 있었음).
- **사용자가 "적용해줘/싹다 반영/롤백"처럼 지시하면 그때는 `src/main`을 바로 수정·롤백한다**(2026-10-14 6·7 반영→롤백→팝업 적용이 그 예). 롤백은 SVN 원본(`.svn/pristine`)과 바이트·해시로 확인하고, 되돌린 최종본은 `구현안_*` 폴더에 해시 매니페스트와 함께 보관해 "다시 만들어줘"에 똑같이 재현한다. **Why:** 우선순위가 바뀌어도 작업을 잃지 않기 위해. **How to apply:** 롤백 전 보관·해시 기록 → 롤백 → 해시 일치 확인 → 메모리·문서 갱신.
- **임시 시험 파일(`*.tmp.test.tsx` 등)은 `src`에 만들었다면 빌드 시작 전에 반드시 삭제**한다(import 없는 파일이 있으면 `TS1208`로 프로덕션 빌드 실패). 빌드·시험 산출물은 세션 폴더(`BUILD_PATH`)로만 내보낸다.
- **사용자가 직접 확정·수정한 설정값(예: 팝업 `WINDOWS`)은 바꾸지 않고 그 값 기준으로 검증·문서화**한다. 서버·시간 관련 결정(PC 시계 대신 서버 시각)은 사용자의 운영 관점 판단을 따른다.
- 한글 경로·정규식을 heredoc으로 넘길 때 역슬래시가 깨질 수 있으니, 경로는 슬래시로 쓰고 복잡한 스크립트는 Write 도구로 파일을 만든 뒤 실행한다. 프로세스 종료 필터는 `Name -eq 'python.exe'`처럼 대상 프로세스만 정확히 지정한다(셸 래퍼까지 종료되는 사고 방지).
