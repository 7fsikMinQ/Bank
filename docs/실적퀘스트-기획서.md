# 실적 퀘스트 (CardQuest) — 기획서 (계획 단계, 코드 없음)

이번 달 카드 실적을 RPG 경험치 바와 동물 캐릭터로 보여주는 위젯 + 탭 전체 화면. 서버·DB·인터넷 없음. 기존 카드 위젯(`CardWidget`)의 데이터·계산을 그대로 재사용한다.

## 1. 결정 사항 (사용자 확정)
- 캐릭터: 동물 이모지. BC바로 🦊 · 현대 ED3 🐻 · 신한 🐱 · 우리다모아 🐰 (나중에 PNG로 교체 가능하게 설계)
- 형태: **A. 홈 위젯(중간 크기)** + **B. 위젯 탭 → 전체 화면(Scriptable WebView)** 둘 다
- 지금은 기획·분석·계획만 확정. 구현은 별도 승인 후.
- 기존 `CardWidget`은 그대로 둔다(둘 중 하나만 홈에 올려도 되고 둘 다 써도 됨).

## 2. 방식 비교와 선택
| 방식 | 판단 |
|---|---|
| 홈 위젯(Scriptable) | **채택(A)**: 홈에서 바로 보임. 정지 그림(애니메이션 불가) |
| 탭 → WebView 전체 화면 | **채택(B)**: 바 차오르기·레벨업 효과 가능. 홈 상시 표시는 불가 |
| 노트북 git 웹서버 | 비채택: 노트북이 켜져 있고 같은 와이파이여야 함 |
| 진짜 앱(Xcode) | 불가: 그램은 Windows. Mac 필요 |
노트북(LG 그램)은 USB로 파일(이미지 등)을 폰에 넣을 때만 쓴다. 평소 사용에는 불필요.

## 3. 레벨·바 규칙 (카드 4개)
입력: 기존 `aggregate()`가 계산한 이번 달 카드별 합계 `v`(원). 음수(취소 초과)는 표시용으로 0으로 고정(`max(v,0)`).

| 카드 | 구간(tiers) | 레벨 | 바(진행률) |
|---|---|---|---|
| BC바로 🦊 | 30만 → 60만 | v<30만: Lv0 / 30만≤v<60만: Lv1 / v≥60만: Lv2(MAX) | Lv0: v/30만 · Lv1: (v−30만)/30만 (30만 달성 때 바가 0에서 다시 시작) · Lv2: 100% |
| 현대 ED3 🐻 | 40만 | v<40만: Lv0 / v≥40만: Lv1(CLEAR) | v/40만 (100%에서 고정) |
| 우리다모아 🐰 | 10만 | v<10만: Lv0 / v≥10만: Lv1(CLEAR) | v/10만 |
| 신한 🐱 | 목표 없음 | v>0: ACTIVE(달성) / v=0: 대기 | 바 없음, 이번 달 금액 + "활동 중" |

- 구간 값은 기존 `CARDS[].tiers`에서 읽는다(숫자를 새로 복사하지 않음 → 목표 변경 시 한 곳만 수정).
- 달성 시 바 색 변경(초록/금색) + `CLEAR`/`MAX` 표시. 미달은 빨강→주황→노랑 계열로 진행률 표시(색만으로 구분하지 않고 퍼센트·텍스트 병기).
- 월 경계: 기존과 동일(KST 1일 0시 초기화, 문자 본문 거래일시 기준). 새 로직 없음.
- 파티 레벨(선택 표시): 달성한 구간 수 합계 / 전체 구간 수 (BC 2 + 현대 1 + 우리 1 + 신한 1 = 5 중 n).

## 4. 화면 설계
### A. 위젯 (중간)
```
10월 실적 퀘스트            파티 3/5
🦊 BC바로   ▰▰▰▰▰▱▱▱  Lv1  35만
🐻 현대ED3  ▰▰▱▱▱▱▱▱  Lv0  8만
🐱 신한     활동 중          12,000원
🐰 우리다모아 ▰▰▰▰▰▰▰▰ CLEAR 10만
10월 8일 현재 · 갱신 14:32
```
- 바는 `DrawContext`로 그린 이미지(둥근 막대) 또는 텍스트 블록 문자 중 **DrawContext 우선, 실패 시 텍스트 바로 자동 대체**.
- 글자 크기는 `FS` 상수 하나로 조절(기존 방식). 탭하면 앱(B)으로 이동(`scriptable:///run/CardQuest`).
- 다크/라이트 모두 가독성 확보(배경 `Color.dynamic`, 막대 트랙 색 별도).

### B. 탭 전체 화면 (WebView)
- 경험치 바가 0 → 현재 값으로 차오르는 애니메이션, 카드별 큰 캐릭터, 이번 달 남은 일수.
- **레벨업 연출**: 지난번에 본 레벨보다 올랐을 때만 한 번 폭죽/문구. "지난번 본 레벨"은 `CardLedger/quest-state.json`(월·카드별 레벨)에 저장·월이 바뀌면 초기화.
- 데이터는 스크립트가 계산해 JSON으로 HTML에 주입(`loadHTML`). 화면은 계산을 하지 않고 표시만 한다(계산 로직 단일화).
- **개발자 미리보기(숨김)**: 타이틀 7번 탭 → 금액을 슬라이더로 바꿔 화면·레벨업 연출만 시험. **실제 데이터·저장 파일에 쓰지 않으며** 화면에 "미리보기" 표시. (실적 숫자를 속이는 용도가 아니라 UI 확인용)

## 5. 구조·파일 계획
```
inbox 문자 파일 ─▶ (기존) ledger-core.js: aggregate() ─▶ 카드별 합계
                                                       ├─▶ quest-core.js: 레벨·진행률 계산(순수 함수)
                                                       ├─▶ CardQuest.js: 위젯(DrawContext) / 앱 실행 시 WebView
                                                       └─▶ quest-state.json: 레벨업 연출 중복 방지
```
- 신규: `scriptable/quest-core.js`(레벨·진행률), `scriptable/CardQuest.js`(소스), `scriptable/CardQuest.single.js`(빌드 산출물, 폰에 붙여넣는 파일), `scriptable/quest-view.html`(WebView용 화면 템플릿, 빌드 시 스크립트에 문자열로 삽입)
- 수정: `scripts/build-single.js`(Quest 단일 파일 빌드 추가), `scripts/test-all.sh`, README/가이드/설계서
- 폰 설치: Scriptable에 `CardQuest` 새 스크립트로 붙여넣기(번역 끄기, `CardCheck`와 같은 검사 스크립트 제공 가능).

## 6. 테스트 계획 (코드 작성 시)
1. 레벨·진행률 단위 테스트: 각 카드 경계값(0, 29만9,999, 30만, 59만9,999, 60만, 음수, 매우 큰 값, 현대 39만9,999/40만, 우리 9만9,999/10만, 신한 0/1원)
2. 월 경계·취소: 합계는 기존 `aggregate` 결과를 그대로 사용한다는 연결 테스트(승인 후 취소 → 0 → 레벨 하락)
3. 위젯 모의 실행(Scriptable 가짜 환경): 오류 없이 완료, DrawContext 없을 때 텍스트 바로 대체, 존재하지 않는 전역 이름 미사용 검사
4. 앱 모드 모의 실행: WebView에 주입되는 JSON 형식, 레벨업 연출 1회만 표시(`quest-state.json` 갱신), 월 바뀌면 초기화
5. 보안 정적 검사: 네트워크·`eval`·클립보드·연락처 없음, HTML 안 외부 URL·외부 스크립트 없음, 주입 데이터 이스케이프(문자 원문을 HTML에 넣지 않고 숫자·고정 문구만 주입)
6. 4개 시간대 반복, 문서·코드 일치 테스트(기존 `docs-sync` 확장)

## 7. 위험·한계 (정직하게)
| 항목 | 내용 | 대응 |
|---|---|---|
| 위젯 애니메이션 | 홈 위젯은 정지 그림, 갱신 시점은 iOS가 결정 | 애니메이션은 B(탭 화면)에서만, 갱신 시각 표시 |
| 이모지 렌더링 | 위젯 `DrawContext`에서 이모지 크기·정렬이 기기마다 다를 수 있음 | 이모지는 `Text`로 그리고 크기 상수화, 아이폰에서 실제 확인 필요 |
| 위젯 메모리 | 이미지를 많이 그리면 위젯이 빈 화면이 될 수 있음 | 막대는 작은 이미지 4장, 실패 시 텍스트 바 |
| WebView 동작 | Scriptable WebView의 실제 애니메이션 부드러움은 폰에서만 확인 가능 | 이 세션은 아이폰 화면을 볼 수 없음 → 계산·코드 구조까지만 검증, 화면은 캡처로 함께 확인 |
| 이미지 교체 | 애니/일러스트는 제가 파일을 만들 수 없음 | `CardLedger/characters/{bc,hd,sh,wr}.png`가 있으면 이모지 대신 사용(저작권 없는 본인 이미지만) |
| 코드 붙여넣기 | 번역기가 변수 이름을 바꾼 전례(`best`→`최고`) | `CardQuest`용 검사 스크립트와 붙여넣기 주의 문서화 |

## 8. 구현 순서 (승인 후)
1. `quest-core.js`(순수 계산) + 단위 테스트
2. 위젯(A) + 모의 실행 테스트 → 폰에서 확인 요청(캡처)
3. WebView 화면(B) + 레벨업 상태 파일 + 테스트 → 폰에서 확인 요청
4. 문서(설치·이미지 교체·문제 해결)·빌드·`CardQuest` 검사 스크립트
5. 최종 검토 3회 후 푸시

## 9. 분석·검토 요약 (10회 분석, 10회 검토에서 정리된 핵심)
- 계산 로직을 새로 만들지 않고 `aggregate()` 결과만 쓰면 카드 위젯과 숫자가 어긋나지 않는다.
- 목표 값은 `CARDS[].tiers`에서 읽어야 목표 변경 시 두 위젯이 함께 바뀐다.
- 위젯은 정지 그림이라 "게임 느낌"은 B 화면이 담당한다. 둘의 역할을 분리하는 것이 가장 현실적이다.
- 신한은 목표가 없으므로 바를 억지로 만들지 않고 "활동 중" 상태로 표시한다(오해 방지).
- BC 30만 달성 시 바를 0으로 다시 시작하는 방식은 사용자 요구와 일치하며, 위젯 숫자(예: 35만)와 바 비율 (35−30)/30=17%이 다르게 보일 수 있으므로 위젯에 `Lv1 → 60만까지 25만` 같은 보조 문구를 함께 표시한다.
- 개발자 숨김 입구는 화면 시험용으로만 두고 실제 합계·저장 파일은 절대 바꾸지 않는다.
