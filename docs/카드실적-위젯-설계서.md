# 카드 월 실적 아이폰 위젯 — 설계·검토 문서

작성일 2026-10-07 · 대상 기기 iPhone 16 Pro (iOS 26.x 또는 iOS 27)
대상 카드: BC 바로 KPASS · 네이버현대카드 Edition3(ED3) · 신한카드 · 우리다모아카드

---

## 0. 결론 (먼저 읽기)

| 질문 | 답 |
|---|---|
| 가능한가? | **가능**. 단, "승인 문자(SMS)가 오는 카드"에 한함. 카드사 앱 푸시/카톡 알림은 읽을 수 없음 |
| DB·서버 필요? | **불필요**. iCloud Drive 폴더에 문자 1건=파일 1개로 저장하면 끝 |
| 앱을 만들어야 하나? | **아니오**. 단축어(기본 앱) + Scriptable(무료) 두 개로 충분. 네이티브 앱은 Mac+Xcode+개발자 계정이 필요해 가장 어려움 |
| 실시간인가? | **문자 수신 → 기록은 즉시**, **위젯 화면 갱신은 iOS가 결정(수 분~1시간 지연 가능)**. 어떤 방식(네이티브 포함)도 이 한계는 동일 |
| 결제 취소(−) | 가능. "취소" 포함 문자는 음수로 합산, 부분취소도 문자의 금액만큼 차감 |
| 매월 초기화 | 자동. 저장된 기록을 "이번 달(KST)"만 필터링해 합산하므로 리셋 코드 자체가 없음 |
| 비용 | 앱 0원. 카드사 문자 서비스가 유료면 카드당 월 수백 원(카드사별 상이, 가입 시 확인) |

## 1. 전체 설계

```
[카드 승인 SMS] ──▶ [단축어 자동화(메시지 수신, 즉시 실행)]
                         │  원문을 가공 없이 파일로 저장
                         ▼
        iCloud Drive/Scriptable/CardLedger/inbox/20261007-123456-4821.txt
                         │  (문자 1건 = 파일 1개)
                         ▼
[Scriptable 위젯] 파일 전부 읽기 → 정규식 파싱 → 이번 달 필터 → 카드별 합산 → 표시
```

### 핵심 설계 결정 (그리고 이유)

1. **단축어는 "원문 저장"만 한다. 파싱·합산은 전부 Scriptable(JS)이 한다.**
   - 단축어의 텍스트 처리(정규식·변수·반복)는 불편하고 디버깅이 어렵다.
   - 원문을 보관하면 문자 형식이 바뀌어도 **코드만 고치면 과거 기록 전체를 다시 계산**할 수 있다.
2. **합계를 파일 하나에 누적(read-modify-write)하지 않는다.**
   - 문자가 동시에 2건 오면 자동화 2개가 같은 파일을 덮어써 금액이 유실된다(레이스).
   - 파일명을 고유하게(일시+난수) 해서 건별로 저장하면 충돌이 원천 차단된다.
3. **DB/서버 없음.** 월 수십~수백 건, 건당 수백 바이트 → iCloud 파일로 충분. 서버를 두면 문자 내용(가맹점·금액)이 외부로 나가는 개인정보 문제만 생긴다.
4. **월 초기화 코드 없음.** 날짜 필터로 해결(KST 기준, 9/30 23:59와 10/1 00:01 경계 테스트 통과).

### 저장 파일 형식 (건당 txt)
```
1588-4000                      ← 1행: 발신번호
2026-10-07T03:12:45Z           ← 2행: 수신 시각(ISO)
[BC카드] 승인 12,000원 ...      ← 3행~: 문자 원문
```

## 2. 필요한 것 (설치·다운로드)

| 항목 | 용도 | 비용 | 비고 |
|---|---|---|---|
| 단축어 (Shortcuts) | 문자 수신 시 파일 저장 | 기본 탑재 | 설치 불필요 |
| **Scriptable** (App Store, Simon Støvring) | 위젯 렌더링·JS 실행 | 무료 | 설정에서 iCloud 사용 ON. 2025~2026에도 iOS 26 대응 수정 릴리스가 확인됨 |
| iCloud Drive | 파일 저장소 | 기본 5GB 무료 | 설정 > Apple 계정 > iCloud > Drive ON, Scriptable ON |
| (개발/테스트용) Node.js 18+ | 이 저장소의 파싱 로직 테스트 | 무료 | 폰 사용에는 불필요 |

**호환성 (iPhone 16 Pro)**: iOS 27은 iPhone 11 이상 지원 → 16 Pro 지원. iOS 26/27 모두에서 단축어 "메시지" 자동화와 Scriptable 위젯 사용 가능(검색으로 확인한 범위 기준, 아래 §8 참조). 다만 **iOS 27 최신 빌드에서의 단축어 동작은 본인 폰에서 §6 테스트로 직접 확인**해야 한다. 이 환경에서는 실제 기기 테스트를 할 수 없었다.

## 3. 선결 확인 사항 (개발 전 반드시 — 여기서 막히면 방법 자체가 안 됨)

| # | 확인 | 방법 | 안 되면 |
|---|---|---|---|
| A | 4개 카드 모두 **승인 SMS**가 오는가 | 카드사 앱/고객센터에서 "결제 승인 문자" 신청. 카톡 알림톡·앱푸시만 오면 불가 | 해당 카드만 수동 입력(§7-C) 또는 Apple Pay 트랜잭션 자동화(§7-B) |
| B | 문자가 **일반 메시지함**에 오는가 | 메시지 앱 > 필터. "알 수 없는 발신자/프로모션"으로 분류되면 자동화가 안 뜰 수 있음 | 필터 끄기, 또는 발신번호를 연락처에 저장 |
| C | 문자 예시 1개씩 확보 | 금액/가맹점만 남기고 카드번호·승인번호 가리기 | 파서 정규식 보정에 필요 (현재는 **가정된 형식**) |
| D | 해외결제·할부·포인트결제 문자 | 같은 방식으로 예시 수집 | 해외는 "원"이 없어 집계 제외 후 ⚠︎로 표시됨 |
| E | 카드별 **실적 인정 기준** | 카드 약관: 전월 이용액 산정 제외 항목(세금, 상품권, 선결제, 무이자 할부 일부 등) | 위젯 값은 "이용금액"이지 "인정실적"이 아님. 제외 키워드를 `exclude`에 추가 |
| F | 목표 금액(현재 코드의 300,000 / 500,000 / 300,000 / 100,000)은 **임의 예시** | 본인 카드 최고 구간 기준으로 수정 | |

## 4. 구축 절차

### 4-1. iCloud/Scriptable 준비
1. 설정 > Apple 계정 > iCloud > 드라이브 > **Scriptable 켜기**
2. Scriptable 실행 → 새 스크립트 2개 생성: `ledger-core`, `CardWidget` → 이 저장소 `scriptable/` 의 내용을 각각 붙여넣기
   (파일 앱 > iCloud Drive > Scriptable 폴더에 `.js` 파일을 직접 복사해도 됨)
3. 파일 앱 > iCloud Drive > Scriptable 안에 폴더 `CardLedger` → 그 안에 `inbox` 폴더 생성

### 4-2. 단축어 자동화 (카드별로 1개씩, 총 4개)
단축어 앱 > 자동화 > + > **메시지**
- 보낸 사람 또는 메시지에 포함: 카드별 키워드(예: `BC`, `현대카드`, `신한`, `우리`) — 한 자동화에 OR 조건이 없어 카드별로 만듦
- **즉시 실행** 선택, "실행 시 알림" 끔

동작(순서):
1. `현재 날짜`
2. `날짜 포맷` → 사용자 지정 `yyyyMMdd-HHmmss`
3. `난수` 1000~9999
4. `텍스트` : (한 줄씩)
   ```
   [발신자]
   [현재 날짜 — ISO 8601]
   [단축어 입력(메시지 내용)]
   ```
5. `파일 저장` → 서비스 iCloud Drive, 경로 `Scriptable/CardLedger/inbox/`, **"저장 위치 묻기" 끔**, 파일명 `[포맷된 날짜]-[난수].txt`

> 주의: "메시지" 자동화에서 발신자/내용을 꺼내는 정확한 변수명·메뉴 구성은 iOS 버전마다 다를 수 있다. 4번 텍스트에 발신자·내용이 **실제로 들어가는지** §6-1로 확인할 것.

### 4-3. 위젯 추가
홈 화면 길게 누르기 > + > Scriptable > **중간 크기** > 위젯 길게 눌러 편집 > Script: `CardWidget`.
- 목표 미달 = 빨강, 달성 = 초록, 제목 옆 `⚠︎N` = 금액을 못 읽은 문자 N건(해외결제 등)
- 위젯을 탭하면 스크립트가 즉시 재실행되어 새로고침(앱이 열렸다 닫힘)

### 4-4. 새로고침을 더 빠르게 (선택)
- 위젯의 `refreshAfterDate`는 **요청**일 뿐, 실제 간격은 iOS가 정한다(WidgetKit 예산: 보통 하루 40~70회, 대략 15~60분 간격).
- 단축어 끝에 Scriptable `스크립트 실행`을 붙여 `Widget.reloadUserWidgets()`를 호출하는 스크립트를 실행하면 문자 직후 갱신을 시도할 수 있다(Scriptable 최신 버전에 이 메서드가 추가되었다고 확인됨). 단, 이 동작은 앱이 포그라운드로 잠깐 열릴 수 있고 잠금 상태에서는 실행되지 않을 수 있어 **기본 구성에서는 넣지 않았다.** 필요하면 추가.

## 5. 취소 처리 규칙 (구현됨, `scriptable/ledger-core.js`)

| 문자 유형 | 처리 |
|---|---|
| 승인 N원 | +N |
| 승인취소 / 취소 N원 | −N (전액취소) |
| 부분취소 N원 | −N (문자에 적힌 금액만큼) |
| 금액 없음(해외 USD 등) | 합산 제외, 위젯에 ⚠︎ 표시 |
| `exclude` 키워드 일치 | 합산 제외 |
| 전월 승인 건을 이번 달에 취소 | 취소 수신 월에 −로 반영(전월 합계는 이미 확정이므로 이번 달이 줄어듦) → 한계로 인지 |

중복 문자(같은 문자가 2번 도착)는 현재 제거하지 않는다. 필요하면 "본문+분 단위 시각" 해시로 제거하도록 확장.

## 6. 테스트 계획

### 6-1. 폰에서 (구축 후 반드시)
1. 단축어 자동화를 열어 "테스트 실행" 없이, **본인에게 보낸 문자/실제 소액결제**로 파일이 생기는지 확인(파일 앱 > inbox)
2. 생성된 txt를 열어 3줄 형식이 맞는지 확인
3. 위젯에 값이 반영되는지, 탭 새로고침이 되는지 확인
4. 잠금 상태 + 화면 꺼진 상태에서 결제 → 파일 생성 여부(최초 잠금해제 이후 기준)
5. 취소 건 결제 → 금액이 줄어드는지
6. 비행기모드→해제 후 iCloud 동기화 지연 확인

### 6-2. 로컬 자동 테스트 (이 저장소, 통과 확인됨)
```
node test/ledger.test.js
```
검증 항목: 승인 합산 / 전액취소 / 부분취소 / KST 월경계(9/30 23:59 vs 10/1 00:01) / 금액 없는 해외문자 / 카드 분류.
※ 테스트용 문자 형식은 **가정**이며 실제 카드사 문자로 교체해야 의미가 있다.

## 7. 대안 비교와 판단

| 방식 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **A. 단축어 + Scriptable (채택)** | 무료·무서버·원문 보관·수정 쉬움 | 문자 필수, 갱신 지연, 초기 세팅 30~60분 | ★ 가장 간단하고 요구 충족 |
| B. 단축어 "트랜잭션" 자동화(Apple Pay) | 문자 불필요 | Apple Pay로 낸 오프라인 결제만. 온라인/네이버페이 불가. 카드의 Apple Pay 지원 여부 확인 필요 | 보조 수단 |
| C. 수동 입력 단축어 | 가장 단순 | 입력 귀찮음 | 문자 안 오는 카드 한정 |
| D. 가계부 앱(뱅크샐러드·토스 등) | 설치만 | 아이폰은 문자·알림 자동 읽기 제한, 카드 연동 방식이라 "실적(전월/당월 기준)" 위젯을 4카드 동시 지원하는 앱은 확인하지 못함 | 기대하지 말 것 |
| E. 네이티브 앱(SwiftUI + WidgetKit) | 디자인 자유 | Mac+Xcode, 개발자 계정(연 $99, 무료는 7일 재서명), 문자 읽기 권한이 없어 결국 단축어가 필요 | 비추천 |
| F. 서버 + 위젯 푸시(iOS 26 APNs) | 거의 실시간 갱신 | 서버·개발자 계정·개인정보 외부 전송 | 과함 |

→ "네이티브 앱으로 만들어도 문자를 앱이 읽을 수 없다"가 결정적: iOS는 SMS 읽기 API가 없으므로 어떤 경로든 **단축어가 입구**다. 따라서 A가 최단 경로.

## 8. 검토 기록과 신뢰도 (정직하게)

여러 번 반복 검토한 결과 반영한 수정:
1. 초안의 "합계를 iCloud 파일에 더해 저장" → 동시 문자 시 유실(레이스) → **건별 파일 저장**으로 변경
2. 단축어 내 정규식 파싱 → 유지보수 불가 → **파싱을 JS로 이동, 원문 보관**
3. "실시간 위젯" 표현 → WidgetKit 예산 때문에 불가 → **기록은 즉시, 표시는 지연**으로 정정
4. 월 초기화 로직 → 제거하고 **월 필터**로 대체, KST 경계 버그 테스트로 검증
5. 부분취소·해외결제·제외항목 처리를 코드/표시(⚠︎)로 명시
6. 메시지 필터링(알 수 없는 발신자) 문제 선결 확인에 추가

**확인된 것**: 파싱·집계 로직(Node 테스트 통과), iOS 27이 16 Pro 지원, WidgetKit 갱신 예산 구조, Scriptable의 iOS 26 대응 릴리스 및 `Widget.reloadUserWidgets()` 존재(검색 결과 기준).
**확인하지 못한 것(폰에서 직접 확인 필요)**: 단축어 "메시지" 자동화의 변수 구성(iOS 26/27), 잠금 상태에서의 iCloud 파일 저장, 4개 카드사의 실제 문자 형식, 카드별 실적 인정 규칙·목표 금액, 각 카드사 문자 서비스 요금.
이 환경에서는 실제 아이폰 테스트와 카드사 약관 조회가 불가능했으므로 "반드시 동작한다"고 단정하지 않는다.
